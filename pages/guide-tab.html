📖 Getting Started Guide

🔐 API Key Authentication

All data endpoints (/suggest, /address/:id) require a valid API key. Keys are domain-bound — the Referer and Origin headers of each browser request must match the registered domain (or a subdomain of it).

✅ Recommended pattern: backend proxy. Store your API key on your own server and proxy requests to G-NAF. The key never reaches the browser, so it can't be stolen from your users. This is how Stripe, Twilio, and Google Maps all recommend using API keys.

1. Generate a Key

  1. Open the 🔑 API Keys tab
  2. Enter your domain (e.g., myapp.com) — www. prefix is stripped automatically
  3. Complete the Cloudflare Turnstile challenge
  4. Click Generate
⛔ Blocked TLDs: Certain high-spam TLDs are blocked from key registration: .tk .ml .ga .cf .gq .top .xyz .vip .club .bond .cam .ink .life .media .wang .quest .host. Configurable via the DOMAIN_SPAM_TLDS env var.

2. Verify Domain Ownership

Keys start in pending status. To activate, add a DNS TXT record:

Type: TXT
Name: @ (or your domain)
Value: gnaf-verify=<verification_token>

After adding the record, click Verify Now in the API Keys tab. DNS propagation typically takes 1–5 minutes. The key status changes to active once verified.

⚠ Important: Remove the TXT record from your DNS after verification completes. Key management uses a separate record (gnaf-mgmt), so leaving gnaf-verify in place does not expose management — but it's still good practice to clean up.

3. Store the Key Safely

Never commit the key to git and never embed it in client-side JavaScript. The key is a secret — treat it like a database password.

4. Use the Key (Backend Proxy Pattern)

The frontend calls your backend, your backend calls G-NAF. The key never leaves the server.

# Node.js / Bun
app.get("/api/suggest", async (req, res) => {
const r = await fetch(
`https://api.yourservice.com/suggest?q=${encodeURIComponent(req.query.q)}`,
{ headers: { "X-API-Key": process.env.GNAF_API_KEY } }
);
res.json(await r.json());
});
# Python / Flask
@app.get("/api/suggest")
def suggest():
r = requests.get(
"https://api.yourservice.com/suggest",
params={"q": request.args["q"]},
headers={"X-API-Key": os.environ["GNAF_API_KEY"]},
)
return r.json()
# Cloudflare Worker
export default {
async fetch(req, env) {
const url = new URL(req.url);
const apiUrl = `https://api.yourservice.com${url.pathname}${url.search}`;
return fetch(apiUrl, {
headers: { "X-API-Key": env.GNAF_API_KEY },
});
},
};
# cURL (server-side testing only)
curl "https://api.yourservice.com/suggest?q=sydney" \
-H "X-API-Key: gnaf_pk_xxx..."

⚠️ What About Browser-Side Use?

You can call the API directly from browser JavaScript by sending the X-API-Key header. It works because the server checks Referer and Origin against your registered domain. But this is not recommended for production:

  • Anyone with browser dev tools can read the key from the network tab
  • The key ends up in browser caches, history, and error reports (Sentry, etc.)
  • The Referer/Origin check is a soft defense — it's spoofable from curl and any non-browser client
  • If the key leaks, you can revoke it, but until then anyone can use it from anywhere

Only use browser-side for prototypes and demos — never for production apps that handle real user data.

⚠️ Key Management — Security

The API Keys tab has three ways to manage your keys:

🔑 Method 1: Using an existing API key

If you have an active API key, enter your domain and paste the full key, then click Manage. The server verifies the key belongs to your domain and shows all keys with revoke buttons. No DNS needed.

🗑 Revoking keys

From the Manage table, click Revoke to revoke a single key. The revoke call uses your existing X-API-Key header — no need to re-enter the full key. The server checks that the auth key belongs to the same domain as the target key. You cannot revoke your own key while other active keys exist (last-key guard). To revoke yourself, use DNS recovery (Method 2).

🔐 Method 2: DNS Recovery (lost all keys)

Lost all your keys? Prove domain ownership via a separate DNS TXT record:

  1. Enter your domain and click Start Recovery
  2. Add gnaf-mgmt=<token> to your DNS (this is different from gnaf-verify used for key activation)
  3. Click Verify DNS & List Keys
  4. After verification, use the Revoke ALL keys button to bulk-revoke every key for your domain in one click

The bulk-revoke endpoint (POST /api/keys/recover/revoke) uses the recovery session token. It does not require the original API key — the DNS proof is your authority.

⚠ Critical: Anyone who can add a DNS TXT record for your domain can list and revoke all API keys. After you finish managing keys via DNS recovery, immediately remove the gnaf-mgmt TXT record from your DNS. Do not leave it active — it is a backdoor to your keys. The recovery session expires after 5 minutes, but the DNS record persists until you delete it.

🔐 Key Expiry & Auto-extension

Every API key has a 90-day sliding-window expiry.

  • New keys get expires_at = now + 90 days
  • Each time the key is used successfully, expires_at is pushed to now + 90 days (auto-extend)
  • Auto-extension only fires when the key is within the last 30 days of its window — capping writes to ~3 per 90-day lifetime per key
  • If a key is unused for 90 consecutive days, it expires and returns 401 KEY_EXPIRED
  • Expired keys can be revived by generating a new key. There is no renewal endpoint.

Bottom line: Use it or lose it. A key used daily stays valid forever. A key generated for a one-off test and forgotten will expire.

📍 Using the Autocomplete

The /suggest endpoint accepts partial Australian addresses and returns ranked matches. Results include G-NAF persistent IDs, formatted display strings, coordinates (GDA2020), and relevance scores.

Query Parameters

ParamRequiredDescription
q✅Search query (min 2 chars, max 200)
state❌Filter: ACT, NSW, NT, OT, QLD, SA, TAS, VIC, WA
postcode❌Filter: exactly 4 digits
limit❌Max results (default 10, max 50)
offset❌Pagination offset (max 1000)
no_cache❌Set to 1 or true to bypass the in-process LRU

API key is passed via the X-API-Key header (not a query parameter). The Referer (or Origin) header must match the key's registered domain.

Examples

# Simple street search
curl "https://api.yourservice.com/suggest?q=12+main+st+sydney" \
-H "X-API-Key: gnaf_pk_abc123..." \
-H "Referer: https://myapp.com"
# State-filtered
curl "https://api.yourservice.com/suggest?q=centre+rd&state=VIC" \
-H "X-API-Key: gnaf_pk_abc123..." \
-H "Referer: https://myapp.com"
# Paginated (page 2)
curl "https://api.yourservice.com/suggest?q=sydney&limit=10&offset=10" \
-H "X-API-Key: gnaf_pk_abc123..." \
-H "Referer: https://myapp.com"

🧠 How It Works

Browser → Cloudflare Edge (DDoS + WAF) → cloudflared tunnel → Bun/Elysia → PostgreSQL

See the ⚙️ System tab for full details on the 7-tier query router, in-memory typo corrector, and G-NAF schema design.

📊 Scoring

Every result includes a score field (0 to ~1.69). Higher = more relevant. The formula combines text similarity with G-NAF data confidence:

score = similarity × (1 + ln(confidenceNorm + 1))
  • similarity (0–1): trigram text match between query and address. For btree tiers (tier0/1/postcode/tier0_number/tier0_locality), similarity is always 1.0 — only confidence_norm drives the ranking.
  • confidenceNorm (0–1): normalises G-NAF's CONFIDENCE column. G-NAF confidence 6 → 1.0 (verified address), 0 → 0.14, NULL → 0.5.

All SQL queries use score DESC as the primary sort, so high-confidence, well-matching addresses always appear first. The ln(confidenceNorm+1) boost is logarithmic — a high confidence address gets a modest bump but never dominates the text similarity.

Cloudflare Tunnel Deployment

# Install cloudflared and authenticate
cloudflared tunnel login
# Create a tunnel
cloudflared tunnel create gnaf-api
# Route DNS
cloudflared tunnel route dns gnaf-api api.yourdomain.com
# Run with Docker Compose
docker compose --profile production up -d tunnel

Data Refresh

G-NAF is published quarterly (Feb, May, Aug, Nov). Update by running the loader with the new data:

docker compose run --rm -e GNAF_DATA_DIR=/path/to/new/data api bun run scripts/load.ts
docker compose restart api
